AIRLOCK DOCUMENTATION · SERVER + DESKTOP

把能力交给调用方，把真实凭据留在本机。

Airlock 是固定路由的凭据隔离层，面向不受信任的 LLM、自动化工具、脚本和第三方 API 中转环境。它把真实 URL、SSH 账号密码和上游 API Key 留在受保护存储中，只把一项受限、可撤销的本地能力交给调用方。

01

安全边界

Airlock 不是开放代理或 VPN。每条路由在创建时绑定一个受保护的固定上游，调用者无法提交任意目标。

  • 调用方使用可撤销的本地 Capability、二次 API Key 或本地 SSH 身份。
  • 上游地址、账户、密码与 Key 只进入本机 SecretStore，不显示在桌面控制面、活动记录或错误提示中。
  • HTTP、SSH 和 LLM 规则分别限制方法、路径、命令、模型、并发和速率。
02

桌面端工作流

在“路由”中创建 HTTP、SSH 或 LLM 入口。SSH 采用本地与上游双会话隔离；LLM 使用独立二次 Key。创建成功后，只把本地入口和对应本地凭据交给需要访问该路由的工具。

路由页的搜索和组合筛选只匹配名称、别名、本地用户名、本地入口、类型、状态、健康和出口模式。批量健康检查只对当前筛选结果执行，且不会发送应用层请求正文或暴露上游目标。

活动页默认只保留脱敏类别、结果、耗时和本地调用者信息；如果显式开启命令审计，完整 SSH 命令可从活动详情查看。现代 OpenSSH 的 scp 默认使用 SFTP；SSH 路由编辑器中的 SFTP 开关默认关闭，启用后会允许上游账号可访问文件的列出、读取、写入、重命名和删除。

03

版本检测与更新

设置页的“检查更新”仅在你点击后访问官方 GitHub Releases 的公开元数据。请求不带路由状态、配置、凭据或用户标识；无法读取公开版本时只显示不可用状态。

Airlock 不会自动下载、安装、重启或打开发布网页。看到新版本后，请前往官方发布页，下载对应产物，校验 SHA-256，并按安装说明手动更新。

04

CLI 安装器

npm 包是经过校验的 macOS 安装器入口，不会在 npm install 时下载、启动应用或修改系统设置。全局安装时使用 airlock-installer，避免与 Server Core 的运维 CLI 冲突。

npx airlock-relay status --json

输出当前包、平台和已发布产物状态。

npx airlock-relay platform --json

输出所有平台契约；计划中的目标不会被标记为已发布。

npx airlock-relay doctor

校验内置 DMG 的 SHA-256，不打开或安装应用。

npm install -g airlock-relay && airlock-installer install --open

校验并原子安装 Airlock.app 到 ~/Applications；显式 --open 才会启动应用。

05

Server Core 与运维

airlockd --mode server 可以脱离桌面端常驻运行。airlock 仅通过服务账户的 Unix Socket 操作固定 HTTP/Wget、SSH 与 LLM 路由；上游 URL、密码和 Key 只能从 0600 JSON 规格文件读取，不会进入命令行参数。

COREairlockd

持久化数据、固定路由策略、SecretStore 与 Direct / Proxy / Auto 出口。默认只监听本机。

OPERATEairlock CLI

创建、启停、删除、健康检查、Host Key 探测和代理配置都在用户专属 Socket 内完成。

OBSERVEWeb UI

独立 token、仅 loopback；只呈现脱敏状态，可进行健康检查、启停与全停。

推荐运维路径

服务器运行核心，管理员使用 SSH 隧道访问 Web UI，或在服务账户下执行 CLI。路由数据入口和控制面都不应直接暴露到公网。

airlock --data-dir /var/lib/airlock --token-file /etc/airlock/control.token routes list

可选 Web UI 使用独立 bearer token 与 loopback listener，只能查看脱敏状态、检查连通性、启停路由和全停。远程访问请使用 SSH 本地端口转发。查看 完整部署与命令行指南。

06

多平台适配

v0.1.4 当前仅发布 Apple Silicon macOS 12+ 测试版。Windows x64、x86（i686）与 arm64、Linux x64/arm64 和 Linux ARMv7（树莓派）的 Core/CLI 交叉编译基线已经就绪，桌面 GUI 也已按系统完成代码移植：Windows 使用当前所有者 ACL 命名管道与原生 Windows Forms 弹窗，Linux 使用当前用户 Unix Socket 与 zenity/kdialog 原生弹窗，凭据存储分别对接 Credential Manager 与 Secret Service；Linux 端口管理直接读取 /proc，不依赖额外工具。Windows 的 NSIS/MSI 与 Linux 的 deb/AppImage 安装包已进入 CI 构建流程，签名与真实硬件验收仍待完成。

目标脚本同时构建 airlockd 与 airlock，不会生成或宣称未发布的桌面包。查看 跨平台适配与验收边界，其中包含 Raspberry Pi、凭据库与安装器的发布前清单。

Give callers capabilities. Keep real credentials local.

Airlock is a fixed-route credential boundary for untrusted LLMs, automation, scripts, and third-party API relays. It keeps real URLs, SSH accounts and passwords, and upstream API keys in protected storage, while callers receive only one constrained, revocable local capability.

01

Security boundary

Airlock is not an open proxy or VPN. Each route is bound to one protected upstream during setup, so callers cannot submit arbitrary targets.

  • Callers use a revocable local capability, secondary API key, or local SSH identity.
  • Upstream URLs, accounts, passwords, and keys enter only the local SecretStore. They are not shown in the desktop control plane, activity log, or error messages.
  • HTTP, SSH, and LLM policies independently constrain methods, paths, commands, models, concurrency, and rate.
02

Desktop workflow

Create HTTP, SSH, or LLM endpoints from Routes. SSH terminates local and upstream sessions independently; LLM routes use an independent secondary key. After creation, give a tool only the local endpoint and that route's local credential.

Route search and combined filters match only names, aliases, local usernames, local endpoints, kind, status, health, and egress. Batch health checks run only against the current result set and never send an application request body or reveal a protected upstream.

Activity is sanitized by default. When command audit is explicitly enabled, full SSH commands can be viewed in the activity detail. Modern OpenSSH scp uses SFTP by default; the SSH route editor keeps SFTP disabled unless explicitly enabled, and enabling it permits file operations available to the upstream account.

03

Version checks and updates

Settings checks the official public GitHub Releases metadata only after you click Check for updates. The request contains no route state, configuration, credentials, or user identifier. An unreachable public release reports only an unavailable state.

Airlock never downloads, installs, restarts, or opens a release page automatically. When a newer version is available, visit the official release page, download the matching artifact, verify its SHA-256, and update manually.

04

CLI installer

The npm package is a verified macOS installer entry point. It does not download, launch software, or change system settings during npm install. Its global executable is airlock-installer, avoiding a collision with the Server Core operations CLI.

npx airlock-relay status --json

Prints the current package, platform, and released-artifact status.

npx airlock-relay platform --json

Prints all platform contracts. Planned targets are never reported as released.

npx airlock-relay doctor

Verifies the bundled DMG SHA-256 without opening or installing it.

npm install -g airlock-relay && airlock-installer install --open

Verifies and atomically installs Airlock.app into ~/Applications; --open explicitly launches it.

05

Server Core and operations

airlockd --mode server runs persistently without the desktop application. The airlock CLI administers fixed HTTP/Wget, SSH, and LLM routes only through the service account's Unix socket. Upstream URLs, passwords, and keys are accepted only from 0600 JSON specifications, never command arguments.

COREairlockd

Persistent state, fixed-route policy, SecretStore, and Direct / Proxy / Auto egress. It is loopback-only by default.

OPERATEairlock CLI

Create, enable, disable, delete, health-check, probe Host Keys, and configure proxy egress through the user-only socket.

OBSERVEWeb UI

A separate token and loopback listener; sanitized state plus health, enable/disable, and stop-all only.

Recommended operations path

Run the core on the server. Reach the Web UI through an SSH local forward, or run the CLI as the service account. Do not expose data ingress or the control plane directly to the public internet.

airlock --data-dir /var/lib/airlock --token-file /etc/airlock/control.token routes list

The optional Web UI has its own bearer token and loopback listener. It can show sanitized status, check health, enable/disable routes, and stop all routes. Use an SSH local forward for remote access. Read the complete deployment and CLI guide.

06

Cross-platform readiness

v0.1.4 publishes a technical preview only for Apple Silicon Macs running macOS 12 or newer. Windows x64, x86 (i686), and arm64, Linux x64/arm64, and Linux ARMv7 (Raspberry Pi) now have a Core/CLI cross-compilation baseline, and the desktop GUI is ported per OS at the code level: Windows uses a current-owner ACL named pipe with native Windows Forms prompts, Linux uses a user-only Unix socket with zenity/kdialog native prompts, and credential storage maps to Credential Manager and Secret Service respectively. Linux port ownership is resolved directly through /proc without an external process tool. Windows NSIS/MSI and Linux deb/AppImage installers are in the CI pipeline; signing and physical-device acceptance remain pending.

The target build produces both airlockd and airlock; it neither creates nor claims an unreleased desktop bundle. Read the cross-platform boundary and acceptance checklist for Raspberry Pi deployment and release prerequisites.

01

セキュリティ境界

Airlock はオープンプロキシや VPN ではありません。各ルートは設定時に 1 つの保護された上流へ固定されるため、呼び出し元は任意の宛先を送信できません。

  • 呼び出し元は取り消し可能なローカル Capability、二次 API Key、またはローカル SSH ID を使用します。
  • 上流 URL、アカウント、パスワード、Key はローカル SecretStore だけに入り、デスクトップ制御面、アクティビティ、エラーには表示されません。
  • HTTP、SSH、LLM のポリシーはメソッド、パス、コマンド、モデル、同時実行数、レートを個別に制限します。
02

デスクトップの流れ

Routes から HTTP、SSH、LLM の入口を作成します。SSH はローカルと上流のセッションを独立して終端し、LLM ルートは独立した二次 Key を使います。作成後にツールへ渡すのはローカル入口とそのルート用認証情報だけです。

ルート検索と複合フィルターは、名前、別名、ローカルユーザー名、ローカル入口、種類、状態、ヘルス、出口だけに一致します。一括ヘルスチェックは現在の結果だけに実行され、アプリケーションリクエスト本文や保護された上流を送信しません。

アクティビティは既定でサニタイズされます。コマンド監査を明示的に有効にした場合のみ、完全な SSH コマンドをアクティビティ詳細で確認できます。最新の OpenSSH の scp は SFTP を既定で使用します。SSH ルートの編集画面では SFTP は既定で無効で、明示的に有効化した場合だけ上流アカウントがアクセスできるファイル操作を許可します。

03

バージョン確認と更新

Settings の更新確認は、クリック後に公式 GitHub Releases の公開メタデータだけを読み取ります。ルート状態、設定、認証情報、ユーザー ID は送信しません。公開リリースに到達できない場合は利用不可だけを表示します。

Airlock が自動でダウンロード、インストール、再起動、リリースページ表示を行うことはありません。新しい版が見つかったら、公式リリースから対応する成果物を取得し、SHA-256 を検証して手動更新してください。

npx airlock-relay platform --json

npx airlock-relay doctor

05

Server Core と運用

airlockd --mode server は Desktop なしで常駐します。airlock CLI はサービスアカウントの Unix Socket だけを使い、固定 HTTP/Wget、SSH、LLM ルートを管理します。上流 URL、password、key は 0600 JSON 仕様からだけを読み、コマンド引数に入りません。

COREairlockd

永続 state、固定 route policy、SecretStore、Direct / Proxy / Auto egress。default は loopback listener です。

OPERATEairlock CLI

create、enable/disable、delete、health check、Host Key probe、proxy configuration を user-only socket 内で行います。

OBSERVEWeb UI

別 token と loopback listener。sanitized state、health、enable/disable、全停止だけを提供します。

推奨する運用経路

server で core を実行し、Web UI は SSH local forward 経由でアクセスします。CLI は service account として実行してください。data ingress と control plane を public internet に直接公開しないでください。

airlock --data-dir /var/lib/airlock --token-file /etc/airlock/control.token routes list

任意 Web UI は別 bearer token と loopback listener を使います。サニタイズ済み status、health、route enable/disable、全停止だけが可能です。リモートアクセスには SSH local forward を使ってください。完全な導入と CLI ガイドを参照してください。

06

クロスプラットフォーム対応

v0.1.4 で公開済みなのは macOS 12 以降の Apple Silicon 向け技術プレビューだけです。Windows x64/x86（i686）/arm64、Linux x64/arm64、Linux ARMv7（Raspberry Pi）には Core/CLI の cross-compilation baseline があり、Desktop GUI も OS ごとにコードレベルで移植済みです。Windows は current-owner ACL Named Pipe と native Windows Forms ダイアログ、Linux は user-only Unix Socket と zenity/kdialog の native prompt を使用し、credential storage は Credential Manager / Secret Service にそれぞれ対応します。Linux の port 所有者は外部ツールに依存せず /proc から解決します。Windows の NSIS/MSI と Linux の deb/AppImage インストーラーは CI pipeline に入っており、sign と実機 acceptance は引き続き未完了です。

target build は airlockd と airlock を生成するだけで、未公開 Desktop bundle を作成または公開済みとして扱いません。Raspberry Pi、SecretStore、release 前の確認は 対応状況と acceptance checklist を確認してください。
