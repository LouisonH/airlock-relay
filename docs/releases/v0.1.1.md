# Airlock v0.1.1 - Technical Preview

Released: July 31, 2026

[English](v0.1.1.md) | [简体中文](v0.1.1.zh-CN.md) | [日本語](v0.1.1.ja.md)

Airlock v0.1.1 is a technical-preview release of the native, fixed-route
credential-isolation relay. It allows an agent, LLM, script, or trusted LAN
device to use a limited HTTP, SSH, or LLM route without receiving the real
upstream address, password, private key, or provider API key.

## What's New

- Run `airlockd` without the desktop application in server mode, administer it
  through a user-only Unix-socket `airlock` CLI, and optionally expose a
  separately authenticated Web UI on loopback.
- Configure multiple SSH mappings on a shared listener, map distinct local
  usernames to protected upstream accounts, use the upstream SSH port you
  specify, rotate local credentials, and run manual health checks.
- Keep the Standard `0600` local secret store as the default to avoid repeated
  macOS password prompts, with macOS Keychain retained as an opt-in stricter
  storage profile.
- Ship a verified npm installer entry point and multilingual product and
  operations documentation, including a GitHub Pages deployment.

## Security and Scope

This is a **prerelease technical preview**, not a production security claim.
The application is ad-hoc signed, but is not Apple Developer ID signed or
notarized. Verify the checksum, download only from the official release, and
follow the Gatekeeper instructions before first launch.

The release passed Go, Rust, frontend, npm-package, artifact checksum, and
strict code-signature checks. It has not received an independent production
security audit. Keep LAN ingress private, use a dedicated least-privilege
upstream account for unrestricted SSH execution, and avoid secrets in audited
SSH command arguments. Read the [security policy](../../SECURITY.md) before
using real credentials.

## Known Limitations

- No Intel macOS, Windows, or Linux installer is published.
- No Developer ID signature or Apple notarization is included.
- Capabilities do not yet support TTL, one-time use, or per-connection approval.
- LLM usage totals are optional in-memory counters, not billing records.
